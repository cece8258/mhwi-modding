## A. ★★ 交接材料里"已探明"的数据**本身可能就是错的** —— 三条都被实测否证

上一版（第十次实战 A）的教训是"交接材料里的**坑**要实测"；这一轮更进一步：**"已探明"的读数也要复核**。

| 交接材料说 | 实测 | 后果 |
|---|---|---|
| §2.2 表格 `A_Collar` 用 `A/Metal/Jewel` | **整列错位一行** —— 那三个材质是 `A_Top_Ribbon` 的；`A_Collar` 在预览里**根本没有材质槽** | 按表建件会拿到错的贴图 |
| （同上）`Tail.001` 材质"见报告" | 也**没有材质槽**；源里真正的归属在 `_extracted\resolved_mats.json` 的 **`slotmap_prefab`**（对象名→材质名）：`A_Collar→A_White`、`Tail→fur` | 漏掉一个材质（`fur` = **无贴图的平涂色**），布类实际是 **9 个**不是 8 个 |
| §2.5 丝袜"绕踝 6.2°" | 最小二乘拟合鞋底剖面得 **9.20°**；且 6.2° 的残差带 10.3mm、9.2° 只有 4.8mm | 按 6.2° 转会**转不够**，脚尖仍翘／鞋底仍斜 |

**做法（可移植）**：
1. **"某件没材质/材质可疑" ⇒ 先查源包的 `resolved_mats.json → slotmap_prefab`**（对象名→材质名 + 贴图），
   它比预览工程权威；预览工程里**没有材质槽**的对象在导入时就会静默变成"无材质"。
2. **角度/长度这类几何量一律自己拟合**（这里用"沿脚长分箱取最低 z + 最小二乘"，再对比两种角度的残差带），
   别信交接材料里"atan(Δz/Δy)"式的算术 —— 它假设了鞋底是平面，而实测那只袜子是
   **rocker（脚尖 9cm 平垫 + 后跟翘）**，不是平面。

## B. ★★ 穿模外推会把网格**推坏**，刚体旋转**不会**

用户："脚尖的袜子形成了**不规则的尖刺**"。判据用 **面法线 vs 它自己三个顶点的顶点法线**的转角
（**自洽**判据；skill 第七次实战 Q 已说过"判网格坏没坏不要跟别的物体比法线"）：

| 状态 | max 转角 | >30° 的三角 | >60° 的三角 |
|---|---|---|---|
| 源几何（预览里原样） | 69.75° | 152 | 22 |
| **只做绕踝刚体旋转** | **69.75°** | **152** | **22** ← **逐项相同 ⇒ 旋转零副作用** |
| 旋转 + 迭代外推（沿身体法线，4 轮） | **164.67°** | 236 | 50 ← **尖刺就是这一步造的** |
| 旋转 + `proj`（投到体表+余量）2mm 限幅 | 109.54° | 165 | 72 |

**三条可移植的规矩**：
1. **交付前对每个改过几何的件都跑一次这个判据，并与"源几何基线"比**（翻倍 = 有尖刺，别只看绝对值）。
   把基线数字写进报告（`第6套` 是 max 69.75° / 152 / 22）。
2. 高曲率区（**脚趾、指尖**）**宁可留穿入也不要推**：那里"最近特征会跳变"，沿法线推会做出
   "每根脚趾一个包"。残余穿入如果**被脚底/脚踝挡住看不见**（`第6套` 是 556 顶点 / 最深 11.5mm）
   就留着；要真收干净只有一条路 —— **"复制目标面外扩 0.6mm 做壳"**（第七次实战 S）。
3. **外推限幅要"累积"**（相对 P0 的总位移），不是"每轮" —— 后者 4 轮可累积 4 倍
   （实测 43.76mm 的失控位移）。而且要**按件给上限**：粗环/足弓这种"天生悬空 12.8mm"的地方要单独放大。

## C. ★★★ 修一个症状会造出另一个症状 ⇒ **两个判据一起看，而且要分带**

用户第一轮："扭腰时裆部被扭变形 + 裆部紧身衣拉长到腿部" ⇒ 我加了 `Z34_修裆部拉伸.py`（身体侧，
把裆的腿权重让给骨盆）。用户第二轮："**裆部确实不怎么扭了，但是大腿的扭曲非常严重**"
⇒ 第一版修过头了。

> ★★★ **别跳过：两条纪律**（本线最贵的一课；也正是**同一个 bug 在 `第5套` 上同样存在**的原因 ——
> 基壳身体在"裆 / 大腿内侧"的 `Hips ↔ 腿` 分配不一致，而 **Z33 只治了噪声与硬跳、
> 没治"中线附近本该更跟骨盆"**）
>
> 1. **必须两个判据一起看**：① 摆姿势下的边长拉伸率（= **症状**）＋
>    ② 同一高度环内 `w_leg` 的 sd（= **副作用**）。
>    只盯 ① 就会造出"大腿扭曲"，而 **② 当时就在报警 —— 我用"这个判据在这里不适用"把它忽略了**，
>    那正是这次的病。**指标报了警，不能因为"解释不通"就无视它。**
> 2. **判据② 必须分带**：**大腿段（预览 z 0.44~0.62）基线 sd max `0.0118` ＝ 护栏**
>    （那里任何 `|x|` 依赖都是凹痕 ⇒ **不许变差**）；**髋部带（0.63~0.70）的 `0.217` 只作参考**
>    （Z33 自己就管这里、实测过且用户认可）。
>
> **★ 回植到其它版本（已回植 `第5套`，2026-09-24）**：只改脚本里的**工程路径一处**，
> 再插进 `Z9` 的 **`Z33 之后 / `Z28`·`Z32` 之前**（带 `nocrotchstretch` 开关），**其余一字不改**；
> 然后对"**已交付的每一份包**"用**原开关**重跑 + `Z14` 验收。
> **⛔ 不要动**：`Z32` 的对齐表、`Z34` 与 `Z32` 的先后顺序、以及**材质配方** ——
> `第5套` 的贴图是**深色**，照抄本轮的 `Base 0.40 / EmiF 2.00` 会让它**变暗**
> （同族：第四次实战 D / 第七次 F —— **系数不能脱离贴图抄**）。

**判据设计**（这一节是本轮最贵的教训）：

| 判据 | 量什么 | 只看它的后果 |
|---|---|---|
| ① **摆姿势下的边长拉伸率** `\|L/L0−1\|`（抬腿 25° / 扭腰 20°，近似 LBS = 绕骨 head 转、按权重加权） | 裆部被扯得多狠（**症状**） | 看不到"大腿上部不再跟腿" |
| ② ★★ **同一高度环内 `w_leg` 的 sd**（Z33 的老口径） | 圆柱部位（腿）本该只随高度变化（**副作用**） | 看不到裆部拉扯 |

第一版**只盯①**：影响区做成**矩形**（`|x|<0.14`，一路管到裆底以下 10cm）
⇒ 同一高度上"内侧跟骨盆、外侧跟腿" ⇒ ①变好、**②从 0.148 涨到 0.256** ⇒ 实机"大腿扭曲严重"。
**判据②当时就在报警，我用"这个判据在这里不适用"把它忽略了 —— 那正是这次的病。**

**两条做法**：
1. **影响区用"以关键点为中心的椭圆"，不要用矩形**：`t = K·(1 − smoothstep(0.55, 1.0, sqrt((x/XR)² + ((z−ZC)/ZR)²)))`。
   椭圆的 |x| 半宽随"离关键点越远"自动收窄 ⇒ 腿段天然不受影响。定稿 `ZC=0.648 / XR=0.040 / ZR=0.035 / K=0.60`
   （预览坐标；裆底 = 0.648）。
2. **判据②必须分带**（把"合理的曲线"与"不该有的凹痕"分开）：

   | 带 | 预览 z | 基线 sd | 处理 |
   |---|---|---|---|
   | **大腿段** | 0.44~0.62 | **0.0118** | **护栏**：任何 \|x\| 依赖都是凹痕 ⇒ 不许变差 |
   | 髋部带 | 0.63~0.70 | 0.000~0.06 | 只作参考（Z33 实测 max **0.217** 且用户认可，同量级即可）|

**定稿读数**（真实流水线；`第6套\_Z34_裆部拉伸_*.txt`）：
```
判据①  max 2.920→1.109（−62%）｜p95 0.513→0.461｜p99 1.519→0.638（−58%）｜>10% 的边 299→281
判据②  大腿段 sd max 0.0102→0.0102（**分毫未动**）｜髋带 0.062→0.241
改动顶点 467（2.8% 全网格；第一版是 1581 / 9.6%）
```
★ 参数扫描表（`_Z34_扫4.txt`）：`XR=0.040 ZR=0.025~0.035 K=0.6` 腿段 sd = 0.0118（安全）；
`ZR=0.048` 起腿段开始超（0.026）；`XR=0.052 ZR=0.070 K=0.9` 是"大腿扭曲"那一版（0.19~0.41）。
**想更狠就必须复核腿段 sd —— 超了就是拿大腿换裆部。**

## D. ★★ 预览 JSON 的权重场 ≠ 工作 blend 的权重场

同一个区域（裆/大腿内侧），**预览 `_X3_preview.json`** 里 `Hips` 均值 **0.616**、
**工作 blend 的 `Body_base`** 里是 **0.279**（后者已经过 第1套 的权重传递 + Z26/Z27/Z31/Z33）。
我拿预览离线（纯 python）调出来的裆部参数（`X_HALF=0.10/K=0.8`）落到工作 blend 后，
`>10%` 的边数反而**涨了 77%**；最后是在**真实权重场**上扫参数才找到最优。

**做法**：纯 python 离线试参数只用来**定方向与公式**；**幅度与边界必须在目标文件上扫**。
给脚本加一个 `dry=1` 模式（**只扫不写盘**、打印判据对照表）—— 一次 1 分钟，比"改—导出—进游戏"快两个数量级。

## E. "衣服灰暗 / 没有反光"：先做 **CB 资源对拍**，再动系数

**不要**先怀疑色彩空间或贴图。做法（`第6套\_cb_full.py`）：把我们的材质与**用户满意的基壳材质**
（`Ch_Standard_Mt__1` 身体）逐项并排打 —— **11 个贴图资源 + 44 个 CB 字段**。

实测结论：`第6套` 的材质与 **第4套、第5套（用户都认可）** 的
`ColorMaskMap / FxMap / FurMap / PanoramaMap` **逐项相同** ⇒ **不是资源指向的问题**；
唯一动过的是 第5套 末期为了治"阳光直射变成一团白光"压下去的两个数：
`fBaseMapFactor` 0.30→**0.10**、`fSpecular` 1.0→**0.30**。

**机理**：白贴图（alpha≥250 区均值 255）+ 自发光占比 96% ⇒ 只剩一片**平的发光**：
没有明暗、没有高光 ⇒ 看着就是"灰暗、没反光"。
**改法**：改回**用户一直满意的身体材质那一档** —— `Base 0.40 / EmiF 2.00 / fSpecular 1.00`
（对白贴图算 等效发光 = 2.00 × 1.00 = **2.00**，正好落在用户认可过的 2.08 / 2.19 上）。

★★ **并且把这三个数做成命令行开关**（`第6套\Z10_只改配方.sh <包名> base=.. emi=.. spec=..`，
约 20 秒一次）—— 观感类参数**永远不要让用户等我改代码**：

| 症状 | 怎么调 |
|---|---|
| 偏暗/发闷 | `base` 抬到 0.5、`emi` 抬到 2.4 |
| 阳光直射过曝 | `emi` 降到 1.6；再不行 `spec` 降到 0.6 |
| 还是"没有反光" | `spec` 已 1.0（标准值）⇒ 问题只在 `assets\RMT` 那张 RMT 图，或者该部位本来就该亮 |

⚠ **这套数字不能跨贴图搬**（skill 第十次实战 §5.3）：第5套 的贴图是**深色**，
`Base 0.40/EmiF 2.00` 会让它变**暗**（等效发光 2.00×0.3 = 0.6）⇒ **同一个 bug 在深色套装上要另定标**。

## F. ★★ 链清单做成"单一数据源"（根治"开关改了、ctc 没跟上"）

`Y1_构建.py` 建完链，把**实际链清单**（链名 / 骨号 / preset）写进 `_Y1_链清单.json`；
`Y4b_物理ctc.py` **优先读它**（内置 SPEC 只当兜底）。
⇒ 任何开关（`nochain`/`nohairchain`/`noearchain`/`nodecochain`/`nopantschain`/`bunnytailchain`…）
增删链条时 ctc 自动跟着变，**永远不会再出现"号与链错配且不报错"**（第五次实战 D 那类）。
另外 `Y1` 的 `DEL_RANGE` 要**同时删旧链骨的两个号段**（`140~193` **与** `206~246`），否则
`eb.new("MhBone_206")` 会被 Blender 静默改名成 `MhBone_206.001` ⇒ 链骨号整体错位。

## G. `FORCE_CHAIN`：整件**没有任何顶点组**的件 ⇒ 按"链投影"白送权重

实测：衣服自带的兔尾 `Tail.001`（86 顶点 / 168 三角）**0 个顶点组**、无材质槽 ⇒ 不处理的话
所有顶点会落到"部位兜底骨"上 = **焊死**。做法：`FORCE_CHAIN[对象名] = 链名`，
逐顶点按 `u = 投影到链轴` 用帐篷函数把权重分给该链的节点（与链权重同一套公式）。
★ 兜底骨也要**按件**给：头发/耳朵的落单顶点必须挂 `Head(4)`，不能按部位兜到 `Chest(2)`
（实测 `TD_Main` 有 160/2405 个顶点没有任何顶点组，挂 Chest 会被胸口拽着动）。

## H. 折线链只在"真是一条弯链"时用（判据：弧长/跨距比）

`第6套` 的肩褶是**三片散开的小片**（空间上前后外各一），我把它们塞进一条折线 ⇒
`order_segs_geo` 排出**往复折线**：**弧长 0.1495 而几何只跨 0.044** ⇒ 节点飘在 15cm 外。
比基尼飘带同理（往复 1.3cm、总弧长 2cm）。
**规矩**：先量 `弧长/跨距`，偏离 5% 以上才用折线；散了的小片走 `chain_tip`（根 = 源骨 head、
尖 = 几何 p95）的**直线轴**。可对照：双马尾的弧长/弦长 = 1.028（只有 2.8% 偏离）⇒ 该用折线。

## I. 死贴图清理：判据就是 `Z14` 的反向检查

`第6套` 删掉了 `Hair.tex`（21MB；该角色 自己的头发贴图，本版换成了 某头发素材 头发 ⇒ 无网格引用、

`tFurMap`/`tPanoramaMap` 指着"的（第3套 踩过）。

## J. 检视工程（`K1_出检视blend.py`）：基壳的导出占位材质**没有节点树**

给用户"自己打开看"的检视 blend 要把源 PNG 挂回材质（工作副本里全是导出用占位材质、纯灰）。
**关键坑**：这些材质**没有 `use_nodes` 或节点树是空的** ⇒ `next(n for n in nt.nodes if BSDF_PRINCIPLED)`
会 `StopIteration`。做法：**整棵节点树重建**（删光 → 添 Principled + Output → 连线 → 挂图），
外加 skill 第七次实战 F 那张表（视口 `MATERIAL`+`TEXTURE`、`Emission Color` 涂黑 / `Strength=0`、
`Metallic=0`、`Roughness≈0.85`、`view_transform='Standard'`、sun 降到 1.0）。
★ `sp.shading.studio_light = "Default"` 这种赋值**要 try/except 包住**（名字不一定存在）。
