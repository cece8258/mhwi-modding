## A. ★★★ 换素材/换做法之前，**先找"能跑的同款参照"，逐像素对拍它的成品贴图**

**这是本轮最贵的一课，也是最省时间的一条。**

现场：用户说"丝袜应该是**渔网袜**"。我从零开始自己发明办法，连试三轮全错
（填洞 → 保留 alpha → 陡化 alpha + 腿皮投影），每一轮都"有实测依据、看起来合理"，每一轮都错。
第四轮用户说了一句"这套丝袜是**不透明**的，你可以参考 `工程根\milfy\1`（同一套衣服）"。

去了之后，**10 分钟定案**：

| 对拍项 | 结果 |
|---|---|
| 两边**源图** `Stockings.png` 的 MD5 | **完全相同** ⇒ 同一张素材 |
| 参照成品 `04_贴图转换\成品\Stockings.png` **= 什么变换** | 逐像素最大差 **0.00** 地等于 `RGB' = RGB源 × (alpha/255)`（**预乘**），且**存成不透明的 RGB** |
| 这条变换在 skill 里有没有 | **有** —— 就是正文那条"作者贴图常把网纹/镂空/线条画在 **alpha 通道**，游戏不透明渲染会丢失 ⇒ 用 PIL 把 **RGB×alpha 预乘**后存不透明版" |
| 我们的成品 `.tex` vs 它的成品 `.tex` | **整条 mip 链逐字节相同**，头部只差**第 36 字节**（我们 `0x1F`=**31**，它 `0x1E`=30） |

**三条可移植的规矩**：
1. **用户在描述"某处不对"时，如果手上有"同一套东西、能跑"的旧工程，先去对拍它的成品文件**
   （贴图用**逐像素**、二进制用**逐字节**、几何用**逐顶点**）。对拍一次的信息量 > 自己试三轮。
2. **参照的"变换"照抄，参照的"格式标志"要按 skill 判** —— 那个参照包是用户**第一个** MHWI 模组
   （"几乎全是 bug"），它的 albedo 用了 **format 30**，而 skill 的普查早已把"albedo 用 30"列为**错误**
   （99.2% 的 albedo 是 31；且"albedo=30"的去重样本里 **15/20 张正是我们自己那个包**，见 §2.6 / §8.2）。
   ⇒ **组合 = 它的预乘 + 我们的 format 31**。
3. 定案后**把"逐字节相同"当验收**：`我们的 .tex` 与 `参照 .tex` 整条 mip 链一致、只差一个格式字节
   —— 这种验收比任何"看起来对不对"都硬。

## B. ★★ 图案画在 **alpha 通道**里的贴图（渔网 / 蕾丝 / 镂空）：四种处置与各自的失败模式

素材：`Stockings.png` 是 **RGB 全白（std = 0.0）、图案 100% 在 alpha 里**
（`alpha==0` 占 62.60% = 菱形网眼；alpha 1→255 是抗锯齿的网线；另有右侧一条实心带）。

| 处置 | 结果 |
|---|---|
| `Y2` 的通用规则"**填满 alpha==0 + alpha 拉平到 255**"（为治脸上的斑驳暗影而设） | **渔网被抹成一个白筒** ← 实机第一轮 |
| **保留 alpha**（想让网眼真透） | 实机是**一片彩色抖动杂色**（`0<a<250` 的抗锯齿边被逐像素裁切，露出底下带颜色细节的身体贴图；mip 链上"直通 alpha"还会让 RGB 与 alpha 不同步） |
| `lerp(皮肤色, 网线色, 原始 alpha)` | 网线被**低值软边稀释成浅灰** ⇒ 腿"整体变白" |
| **★ 预乘 `RGB' = RGB源 × (alpha/255)`，然后 alpha 全置 255** | **正解**（= 作者原意 = 参照工程的做法） |

**三条可移植的规矩**：
1. **换素材先量一句"`alpha==0` 占比 + RGB 是不是常量"**：RGB 是常量（std 0）就说明**图案在 alpha 里**，
   绝不能走"填洞"那条路。
2. **再看 alpha 直方图**：本图 `alpha>=1` 占 **37.40%**、但 `>=250` 只 **5.13%**（从 1 平滑衰减）
   —— "低值软边占大头"的掩码**直接当 lerp 权重会把线条稀释成浅灰**。要它变实，得先"陡化"
   （`a' = clip((a/255−0.10)/(0.50−0.10),0,1)`），但**预乘路线根本不需要这一步**。
3. **验收 = 解码成品 `.tex` 的 mip0**，不是看文件大小。可复制的解码链：
   ```
   .tex 前 184 字节头 + mip 表 → 取 mip0 载荷
   用 texconv 自产的单级 BC7 DDS 头当模板（dwMipMapCount 改成 1）
   → texconv -f R8G8B8A8_UNORM -m 1 → 读字节 → reshape(H, W, 4)
   （★ 别手搓 DDS 头；字段顺序极易错，用"能跑的同款 DDS 的头"最稳）
   ```

## C. **首次导入"裸 FBX"**：对象名/骨架名/材质名都会被导入器改，一律按"对象引用"与"前后差集"判

素材从来没进过预览工程 ⇒ `X1` 里自己 `bpy.ops.import_scene.fbx()`。**三个坑**：

| 坑 | 实测 |
|---|---|
| **对象名会被重名改写** | 素材里的 `Tail` 在预览工程里已有 `Tail`(身体) 与 `Tail.002`(头发) ⇒ 导入后变成 **`Tail.003`** |
| **骨架对象名是导入器给的** | 叫 **`Armature.007`**（预览里已占用 `.001~.006` 与 `.1`） |
| **材质名会被重名改写** | 素材里的 `Metal` 变成了 **`Metal.001`**（写错名字会静默漏挂材质） |

**做法**：① 导入前后取 `set(bpy.data.objects)` 的**差集**拿到"新导入的那批"；
② 用"去掉尾部 `.NNN`"的**基准名**建索引（只吃纯数字后缀，`NO.1` 不受影响）；
③ 骨架**按对象引用**取，绝不按名字；④ 把 `pre["cloth_arm"]` / `pre["hair_arm"]` 写进采集 JSON，
下游（`Y1`）读它 —— 换素材时一行都不用改。

## D. "逐槽定材质"常常是**伪命题**：同一件的各材质槽**共享同一套 UV** ⇒ 按件归组

素材每件有 2~5 个材质槽，名字是通用的 `NO.1` / `NO.1-1` / `NO.1-2` / `Fur1` / `Metal`
（不是贴图名，也不代表"第几套 UV"）。**判据**：逐槽把 UV 包围盒算出来比 ——

```
Choker  : NO.1   u 0.033~0.107   ；NO.1-1 u 0.055~0.122   ⇒ 区间**互相重叠**
Suit    : NO.1   u 0.037~0.969   ；NO.1-2 u 0.037~0.957   ⇒ 几乎完全重合
```
⇒ 它们只是**同一套 UV 上的不同材质实例** ⇒ **按"件"归组**（与素材作者自己写的上色脚本一致），
用 `NO.*` → 哨兵 `"__PIECE__"`（归到该件的 mainkey），`Fur*` → `FUR`、`Metal*` → `METAL`。

★ **但"按材质拆件"仍然要做**（导出器每网格只写**材质槽 0**），而且**要跳过 0 面槽**
（本素材 `Suit` 的槽 2 就是 0 面；拆件逻辑里"该槽没有面就 continue"天然跳过，不用特判）。

## E. ★★ 部位**空了** ⇒ 导出**直接中止**；用**通用**的"隐形载体"兜底

去掉兔尾后 `wst` 一个网格都没有，导出预检报 **`f_wst040_0010.mod3: 没有网格 (NoMeshesInCollection)`**
并中止整条流水线。正文早写过：**不能发空 mod3，也不能删 mod3（游戏会回落到原版模型）**。

**做法（`Y1` 里加一段通用的空部位兜底，不特判某个部位）**：
```
对每个部位：若集合里没有任何 MESH：
  取 Body_base 的某一小块（按 z 带选，如骨盆 z∈[0.00,0.10]）
  → 绕**该批顶点的质心**缩到 0.9 倍（质心在身体内部 ⇒ 每点往里挪 10% ⇒ 严格在体内）
  → 权重沿用那批身体顶点（只保留**本部位骨架里存在**的骨名）
  → 材质取 MAT_OF[部位] 的第一个键（保证它在本部位的 mrl3 里存在、且贴图已随包发出）
  → 挂本部位骨架 + 进本部位集合
验收：算载体每个顶点到身体表面的**有符号距离**，要求全为负（本版 −2.92 ~ −13.65 mm ✓）

> ⚠️ **这个「复制身体一小块」的做法在第十三次实战里被证明是危险的、已被取代** ——
> 选的 z 带一旦落在**手臂那一层**（`第11套` 的 `arm` 部位就是），就会把**手臂连手一起复制**出来
> （游戏里「多出一只白手 + 沿手臂两条白条」）；而且「缩到 0.9 倍」在起伏大的地方只剩**几毫米**余量、
> 动画一动就冒出来（实测 11.4% 露在体外、最深 +29.6 mm）。
> **空部位改用「3 顶点占位件」**，见**第十三次实战 C**（3 顶点 / 1 面、骨盆正中、100% 绑 `MhBone_013`）。```
★ **每出一个新变体都要跑一次导出预检** —— 这类"某个开关把某部位清空"的错误只在**那个开关组合**下出现。

## F. ★★ 姿态下的穿模判据：**配对法**；"有符号最近距离"会被**最近特征跳变**污染

v4（去手套）要量"屈指时手指会不会顶出袖子"。**两个判据并排看**：

| 判据 | 静止 | 屈指 45°（16 根指骨各弯 45°） |
|---|---|---|
| 到皮肤表面的**有符号最近距离** | 陷入 20（0.36%），最深 −4.9 mm | 陷入 **229**（4.10%），最深 **−15.6 mm** |
| **配对法**（静止时给每个衣物顶点配一个最近的皮肤顶点，之后**一直用这一对**，量配对距离的变化） | Δ 全 0（**零点自检通过**） | 中位 +0.000 / p1 −3.36 / **min −6.80 mm** |

**读法**：静止时袖子间隙中位 **+5.7 mm**，屈指后局部收窄 **6.8 mm** ⇒ 最坏只剩 **1 mm 级**净穿入，
**不是**那个 −15.6 mm（弯曲时"最近点"从这根指跳到邻指/指节，读数是假的）。

**三条可移植的规矩**：
1. **姿态下的穿模一律用配对法**（正文 §"贴身衣物的自适应间隙"里那条）；
   有符号最近距离只在**静止、低曲率**时可当参考。
2. **配对法必须做零点自检**：把 `SP_now/BP_now` 传成静止值，Δ 必须恒为 0 —— 不通过就是代码错。
3. 想改善时**先看权重残差**：本版 `Z32` 把袖子按"最近**面**的重心插值"对齐，中位/p90 的 L1 差已是 **0.000**、
   但 **max 还有 0.289** ⇒ 这 0.29 在 45° 屈曲下就是几毫米。
   ⇒ 若要再收，把口径换成"最近皮肤**顶点**"（配对点与衣物逐位同权重）。

## G. 链条取点的两个"静默出错"（`seg_nodes`）

`seg_nodes` 的取点规则是"该顶点的**链组权重和 > 非链组权重和**"。两处会**静默**给假值：

| 症状 | 根因 | 修法 |
|---|---|---|
| 折线**退化成 0 长度**（弧长 0.0000） | 兔尾的顶点大量是 `{Hip_Root_Tail.001:0.4, Hips:0.6}` —— **主导组是链组、但权重和更小** ⇒ 两个段组都收不到点 | 该链改用 `chain_tip`（根 = 源骨 head、尖 = 几何 p95 的**直线轴**） |
| **往复折线**（节点飘在几何外） | 段组是"散开的小片"（颈饰 11 段 = 上圈 + 下垂两簇）⇒ 最近邻游走排出往复 | 同上；或用 **弧长/弦长 > 2.5** 判 |

**做法**：把判据写进建链代码自动报 ——
```
弧长 < 0.1mm            ⇒ 打 "!! 折线退化成 0 长度（段组收不到点）⇒ 改用 chain_tip"
弧长/弦长 > 2.5         ⇒ 打 "!! 往复折线（节点会飘在几何外）⇒ 改用 chain_tip"
```
★ 与"段组编号不沿链"是**两条不同**的坑：那条要 `order_segs_geo` 按几何排序，这条要换成直线轴。

## H. 交接材料里的"已探明"要复核：本版三条

| 交接材料说 | 实测 |
|---|---|
| 兔耳 `Head_Root_Headband.*` "6 段 = 每耳 3 段" | **右 4 段 / 左 2 段**（按质心 x 符号分完就是 4+2）⇒ 节点数按实际段数取 |
| 骨架"逐位 0.000000 m" | 躯干/四肢主骨确实如此；**手指远节差 ~1.0 mm**（`Ring/Little/Index Distal`）—— 仍同源，`SCALE=1.0` |
| `Suit` 的 `Hip_Root_Suit.*` 是"裙摆/褶边" | 用户纠正：`Suit` 是**没有裙摆的紧身连体衣** ⇒ 那 8+8 个段组是**腿洞/髋部的蕾丝边**，在**方位角**上绕腿洞一圈（z 几乎不变、y 从 −0.066 到 +0.080）⇒ **不是一条链**，硬拉一条 4 节点链会得到"绕髋一圈的怪折线"。改成**每侧 2 条 2 节点链**（前弧 3 段 / 后弧 5 段） |

★ 规矩：**段组是"沿一条线"，还是"绕一个圈"？先量它的质心分布再决定** ——
沿线的走 `chain_tip`/`seg_nodes`，绕圈的**必须拆成弧**。
